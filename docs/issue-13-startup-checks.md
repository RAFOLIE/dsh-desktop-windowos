## 实现

- 已安装候选 120 秒，npx 300 秒；实际轮询使用同一 `startup_policy::poll` 判定。已有就绪服务走 attach，不执行候选发现。
- 无帮助子进程：读取 npm/pnpm shim 指向的真实 CLI 包和 Node 解析路径下的 web-app startup 参数声明。核验包名、SemVer、bin 与导出入口；未知返回兼容回退，不传 `--no-open`。每次重新读取，无旧缓存。未知安装可能仍由 DSH 自行打开浏览器。
- 相同目标/工作目录去重；完整 DSH_CMD 不改写。直接 npx 使用固定 `.dsh` 工作目录，避免与其他候选改变会话工作区。
- 启动状态包含来源、阶段、已用秒数、预算；重载可取最近状态。启动门闩避免重复启动链，手动重启等待也计入活动阶段。
- Web 入口：启动/升级期间继续等；终止状态及时反馈。无活动任务仍保留 120 秒兜底；活动任务最多等待 2400 秒后结束本次网页请求，不终止后端任务。
- writer-lock 错误显示路径和文件内 PID（PID 不是活跃占用的证明）；不删锁、不自动重试其他候选。进程退出后最多 500 ms 等待输出流结束，避免末尾错误读取竞态。
