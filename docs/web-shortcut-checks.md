# 网页快捷方式修复（v1.6.52）

## 根因与行为

旧默认 `.url` 直接指向 `http://127.0.0.1:3080`。在已安装的 DSH 0.1.5-rc.2 上，无 Cookie 请求实测返回 HTTP 401。DSH BrowserAuth 的进程登录链接会交换浏览器自己的 Cookie；桌面 WebView2 的登录 Cookie 不能直接共享给默认浏览器。

应用启动时注册当前用户的 `dsh-desktop-web` 协议，命令是带引号的当前 exe 路径加固定 `--open-web`。不使用 `%1`，外部 URI 的路径、查询和参数不会进入执行命令。原来的默认 `DeepSeek Harness Web.url` 被迁移到 `dsh-desktop-web://open`，不保存 token。首次升级后需要重新打开桌面应用一次。

冷启动使用正常后端启动链；已有实例通过单实例回调处理。网页请求等待服务就绪、避开正在进行的内核更新，然后验证当前进程登录链接，再交给默认浏览器。重叠请求合并。缺少外部后端凭据、服务超时或浏览器失败时通过桌面提示说明，不自动重启外部后端。

旧 npm 插件可能再次生成裸地址；应用运行时每 3 秒检查一个已存在的小型默认快捷方式文件并按需修复，不扫描桌面。不创建已被删除的快捷方式，不修改自定义地址或其他端口。主题、会话、用户配置与 npm 插件版本不变。

## 检查

- Rust `web_shortcut::tests`：迁移、保留图标和自定义 URL、幂等、严格启动参数匹配。
- Rust `dsh::browser_handoff_tests`：查询值编码、成功状态、拒绝失效令牌和错误状态、错误信息不携带 token。
- 原有 Rust 测试通过；合计 19 项通过，1 项只读主机诊断按定义忽略。
- `tests/appearance-ui.cjs`：增加等待 / 鉴权失败 / 关闭提示 / 成功清除状态的事件回归，保留原设置与聊天草稿检查。
- Windows 原生测试：临时独立协议注册到一个只写测试标记的无窗口 exe，实际打开临时 `.url`，确认正确分发；测试后删除临时协议注册。未模拟用户鼠标键盘操作。
- `pnpm tauri build` 构建发行 exe，交付前检查版本资源、最终 JS/CSS 内嵌指纹和 SHA-256。

本轮没有停止用户后端以执行真实登录重启测试。代码依据本机官方 DSH BrowserAuth 实现：进程 token 在该进程生命周期中可以重复交换；每个浏览器自行获取签名 Cookie。外部来源缺少 token 时提示使用原始终端登录链接，不能宣称已自动登录该来源。
